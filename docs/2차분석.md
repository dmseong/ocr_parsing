# OCR 파싱 분석 및 개선 계획 (2차)

## 1. 문제 상황 분석
사용자 피드백에 따르면 **Sample 03**과 **Sample 04**에서 **실중량(Net Weight)**이 **총중량(Total Weight)**과 동일한 값으로 잘못 추출되었습니다.

| 샘플 | 실제 실중량 | 추출된 실중량 | 상태 | 원인 추정 |
| :--- | :--- | :--- | :--- | :--- |
| **sample_03** | 130 kg | 14,080 kg (총중량) | **오류** | 파서가 "총중량" 라벨의 "중량" 부분을 "실중량" 라벨로 오인함. |
| **sample_04** | 1,320 kg | 14,230 kg (총중량) | **오류** | 상동. |

## 2. 원인 식별: "중량" 패턴의 모호성
지난번 코드 개선 시, `실중량`을 더 잘 잡기 위해 범용적인 패턴을 추가했습니다:
```python
# 3. Net Weight (실중량)
self.matcher.add("NET_WEIGHT_LABEL", [
    ...
    [{"TEXT": "중"}, {"TEXT": "량"}],  # <--- 문제의 패턴
    [{"TEXT": "중량"}]                # <--- 문제의 패턴
])
```
그러나 한국어에서 **총중량**, **공차중량**이라는 단어 안에도 **중량**이 포함되어 있습니다.
OCR 텍스트가 위에서 아래로 읽힐 때, **총중량**이 먼저 나오므로 파서는 이를 **실중량** 라벨로 착각하고 옆에 있는 숫자(총중량 값)를 가져가 버린 것입니다.

## 3. 개선 계획
### 3.1. 파싱 패턴 수정 (Specificity 강화)
- **조치**: `NET_WEIGHT_LABEL` 매처에서 범용적인 `중량`, `중 량` 패턴을 **삭제**합니다.
- **이유**: "실중량"은 반드시 "실"이라는 글자가 있거나, 문맥적으로 구별되어야 합니다. 모호한 패턴은 오탐(False Positive)을 유발합니다.

### 3.2. 검증 프로세스
- 수정 후 `verify_parser.py`를 재실행하여 Sample 03, 04의 실중량이 정상적으로 추출(Total - Tare)되는지 확인합니다.
