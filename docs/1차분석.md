# OCR 파싱 분석 및 개선 계획

## 1. 초기 코드 구조
- **엔진**: spaCy (한국어 모델 `ko_core_news_sm`).
- **방식**: 규칙 기반 매처 (Rule-based Matcher).
    - **1단계**: 유연한 패턴을 사용하여 라벨(예: "총중량", "실중량")을 찾음.
    - **2단계**: 라벨 뒤의 "문맥 윈도우"(다음 15개 토큰)를 탐색.
    - **3단계**: 해당 윈도우 내에서 가장 적합한 숫자(정규식 매치)를 추출.
- **현재 상태**: 구현 완료 및 4개 샘플에 대해 검증 수행.

## 3. 식별된 문제 및 노이즈 패턴
1.  **시간 패턴 노이즈**: 단순한 `\d:\d` 정규식은 `02 : 13`과 같이 띄어쓰기가 포함된 시간을 놓침. 이로 인해 "02"가 중량으로 잘못 인식됨.
2.  **라벨 모호성/OCR 오류**: `sample_01`에서 표준 라벨("총중량")이 깨지거나 누락됨. 파서가 라벨에만 의존하기 때문에 추출에 실패함.
3.  **작은 숫자 함정**: 파서가 매칭된 첫 번째 숫자를 맹목적으로 수용함. 트럭의 중량이 "2"나 "5"처럼 한 자리 수일 가능성은 희박함.

## 4. 개선 계획 (코드 리팩토링)

### 개선 A: 노이즈 제거 강화
- **조치**: `_extract_best_number` 정규식을 업데이트하여 공백이 포함된 시간 형식(`\d+ \s* : \s* \d+`)을 포착하고, 숫자 추출 전에 이를 제거하도록 함.

### 개선 B: "Bag of Weights" (중량 꾸러미) 폴백 전략
- **개념**: 라벨 기반 추출이 실패할 경우, "수학적" 추론으로 대체함.
- **로직**:
    1. 문서 *전체*를 스캔하여 "[숫자] kg" 형태의 모든 토큰 시퀀스를 찾음.
    2. 모든 후보를 수집함 (예: [14080, 7470, 5010]).
    3. `총중량`이나 `공차중량`이 누락된 경우, `A (총중량) = B (공차중량) + C (실중량)` 공식을 만족하는 조합이 있는지 확인함.
    4. 이 로직을 기반으로 누락된 필드를 자동으로 채움.

### 개선 C: 중량 크기 필터
- **조치**: 추출된 숫자가 100 미만인 경우(트럭 계근표의 경험적 수치) 무시함. 단, 다른 후보가 없는 경우는 제외. 이를 통해 Sample 02의 "2"와 같은 오류를 필터링함.
